# お客さん用のリアルタイム金額表示

## 接続のしかた

1. レジとお客さん用端末を同じWi-Fiまたはテザリングに接続し、最新ページを開く。
2. レジの「お客さん表示」を押す。接続用QRは自動で準備される。
3. お客さん用端末のカメラでQRを読み、リンクを開く。すでにcustomer.htmlを開いている場合は「レジのQRを読む」でもよい。
4. お客さん用端末に返答QRが出る。最初のQRを作ったレジの同じタブに戻り、画面内の「返答QRを読む」を押して、そのQRを読む。レジ側は標準カメラや別タブで読まない。
5. 接続後はお客さん画面が大きな金額表示になり、マークの追加・減算・会計クリアが自動反映される。

カメラが使えない場合は、QR画像を保存して「QR画像を選ぶ」で読むか、詳細欄の接続リンク/返答コードを貼り付ける。画像は端末内で処理し、アップロードしない。

## 接続準備が失われた場合

レジを再読込・終了すると、最初のQRに対応する接続準備は失われる。「お客さん表示」を開き直すと新しいQRを自動生成するので、お客さん端末でそのQRを読み、新しく出た返答QRを同じレジ画面で読む。古い返答QRは再利用しない。返答の読取ボタンは準備ができるまで無効。有効期限が切れていれば新しいQRを用意して読み直しを案内する。

## 動作と制限

- QR交換は初回接続時のみ。会計ごとのQR読取は不要。
- 接続用QRは生成から10分間有効。両端末の時計は自動設定にする。成立済みの接続が10分で終了することはない。
- 両方の画面を開いたまま利用する。再読込、ブラウザ終了、端末のスリープで接続が切れた場合は再度QRを交換する。
- 1つのレジにお客さん用表示1台を接続する。追加の接続作成は以前の接続を終了する。
- 最新金額を1秒ごとにも送信する。8秒以上更新が途絶えた場合、または切断が分かった場合、お客さん画面は古い金額を非表示にする。ブラウザのバックグラウンド制限により検出時刻には幅がある。
- 会計完了後は次の会計の0円へ切り替わる。通信機能が失敗してもレジの計算・履歴保存は継続できる。
- WebRTCの直接通信を利用する。Googleの公開STUNサーバーを接続先探索に使用する。回線・ファイアウォール・Wi-Fiの端末間通信禁止によって接続できない場合がある。TURN中継は今回導入しておらず、任意の異なる回線での接続成功は保証しない。
- iPad Safariの実機カメラ、別々の物理端末・各会場Wi-Fiの検収は未実施。現地の接続テストを行う。

## 共有する情報

WebRTCデータチャネルで送るのはバージョン、種別、合計金額、連番のみ。お客さん側へ売上履歴、書籍明細、色・分類、設定、バックアップは送らない。お客さん側から会計を変更する機能はない。履歴は引き続きレジのIndexedDBに保存する。

QRには一時的な接続情報（セッションID、DTLSフィンガープリント、ネットワーク候補、有効期限）を含む。目の前の表示端末とだけ交換し、公開リポジトリやログへ保存しない。リンクの接続情報はURLフラグメントに入れ、お客さん側の返答準備後にアドレス欄から取り除く。

## マーク移行

現在のマークは赤・黄・緑・白・青・白丸の「そ」。最新のユーザー指定により6種類とも100円の初期設定へ一度再構成する。価格候補は100/200/400円。以後に変更した設定はmarkerVersion:2により保持する。確定履歴・取消記録・価格snapshot・採番を改変しない。旧ピンクを含むバックアップと途中会計も保持可能。

## 実装

`src/signaling.js`: 圧縮したQR接続情報、期限・セッション・金額パケット検証。

`src/amount-link.js`: WebRTC接続、QRによるoffer/answer交換、金額送信、ハートビートと切断判定。

`src/qr.js`: QR生成とカメラ/画像の端末内読取。ライブラリは接続機能を開くまで読み込まない。

`src/customer-controls.js`: レジ側の接続操作。`customer.html`と`src/customer.js`: お客さん用表示。

## iPad Safariで返答読取後につながらない場合

1. 両方のページを再読込して修正版を開く。
2. レジの「お客さん表示」内で「iPad / Safariでつながらないとき」を開き、「Safari用に接続を準備（カメラ許可）」を押してカメラを許可する。
3. 作り直されたQRをお客さん端末で開く。
4. お客さん画面でも「iPad / Safariでつながらないとき」を開き、「Safari用に返答を準備（カメラ許可）」を押して許可する。返答QRが作り直される。
5. 新しい返答QRを元のレジ画面内のボタンから読む。両方のSafariを前面に表示して待つ。

カメラ許可によりローカル接続候補の取得を試す任意の対処。ボタンを押したときだけvideo:true/audio:falseで取得し、QR接続情報の生成後・失敗時に全トラックを停止する。カメラ映像を通信へ追加・録画・送信しない。Safariのバージョンや回線により効果がない場合もある。WebKitの[公式説明](https://webkit.org/blog/7763/a-closer-look-into-webrtc/)と[関連する制限の報告](https://bugs.webkit.org/show_bug.cgi?id=174500)を参考にした。実機での解消確認は未実施。

20秒経過だけでは切断と判定しない。「通信の確認に時間がかかっています」と表示し、1分後も成立しなければ「接続を確認できません」と表示する。時間経過による表示は通信自体を閉じず、後から成立すれば自動で復帰する。ブラウザの一時的disconnectedは復帰待ち、failedとチャネルエラーは接続失敗、チャネルcloseは終了として区別する。

つながらない場合は両画面の「接続状況（問い合わせ用）」を確認する。接続・ICE・データチャネルの状態だけを表示し、IPアドレスやSDP、売上データを含めず、外部へ自動送信しない。同じWi-Fi名でも端末間通信が禁止されることがある。Safari用の準備を両端末で行っても失敗する場合は、別の回線で新しいQRを交換する。TURN中継は未導入なので、全回線での接続を保証しない。
