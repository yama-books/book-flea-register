# お客さん用のリアルタイム金額表示

## 接続のしかた

1. レジとお客さん用端末を同じWi-Fiまたはテザリングに接続し、最新ページを開く。
2. レジの「お客さん表示」→「接続用QRを作る」を押す。
3. お客さん用端末のカメラでQRを読み、リンクを開く。すでにcustomer.htmlを開いている場合は「レジのQRを読む」でもよい。
4. お客さん用端末に返答QRが出る。レジで「返答QRを読む」を押し、そのQRを読む。
5. 接続後はお客さん画面が大きな金額表示になり、マークの追加・減算・会計クリアが自動反映される。

カメラが使えない場合は、QR画像を保存して「QR画像を選ぶ」で読むか、詳細欄の接続リンク/返答コードを貼り付ける。画像は端末内で処理し、アップロードしない。

## 動作と制限

- QR交換は初回接続時のみ。会計ごとのQR読取は不要。
- 接続用QRは生成から10分間有効。両端末の時計は自動設定にする。成立済みの接続が10分で終了することはない。
- 両方の画面を開いたまま利用する。再読込、ブラウザ終了、端末のスリープで接続が切れた場合は再度QRを交換する。
- 1つのレジにお客さん用表示1台を接続する。追加の接続作成は以前の接続を終了する。
- 最新金額を1秒ごとにも送信する。8秒以上更新が途絶えた場合、または切断が分かった場合、お客さん画面は古い金額を非表示にする。ブラウザのバックグラウンド制限により検出時刻には幅がある。
- 会計完了後は次の会計の0円へ切り替わる。通信機能が失敗してもレジの計算・履歴保存は継続できる。
- WebRTCの直接通信を利用する。Googleの公開STUNサーバーを接続先探索に使用する。回線・ファイアウォール・Wi-Fiの端末間通信禁止によって接続できない場合がある。TURN中継は今回導入しておらず、任意の異なる回線での接続成功は保証しない。
- iPad Safariの実機カメラ、別々の物理端末・各会場Wi-Fiの検収は未実施。現地の接続テストを行う。

## 共有する情報

WebRTCデータチャネルで送るのはバージョン、種別、合計金額、連番のみ。お客さん側へ売上履歴、書籍明細、色・分類、設定、バックアップは送らない。お客さん側から会計を変更する機能はない。履歴は引き続きレジのIndexedDBに保存する。

QRには一時的な接続情報（セッションID、DTLSフィンガープリント、ネットワーク候補、有効期限）を含む。目の前の表示端末とだけ交換し、公開リポジトリやログへ保存しない。リンクの接続情報はURLフラグメントに入れ、お客さん側の返答準備後にアドレス欄から取り除く。

## マーク移行

現在のマークは赤・黄・緑・白・青・白丸の「そ」。既存設定のピンクだけを「そ」の未設定項目へ移行し、価格対応を再確認する。他の5色の対応は保つ。確定履歴・取消記録・価格snapshot・採番を改変しない。旧ピンクを含むバックアップと途中会計も保持可能。

## 実装

`src/signaling.js`: 圧縮したQR接続情報、期限・セッション・金額パケット検証。

`src/amount-link.js`: WebRTC接続、QRによるoffer/answer交換、金額送信、ハートビートと切断判定。

`src/qr.js`: QR生成とカメラ/画像の端末内読取。ライブラリは接続機能を開くまで読み込まない。

`src/customer-controls.js`: レジ側の接続操作。`customer.html`と`src/customer.js`: お客さん用表示。
