# 確定仕様と実装用の設計判断

基準日: 2026-10-30 JST。ユーザーの引継ぎ本文と追加指示を正本とし、画像は視覚的参考とする。

## 必須仕様

| 項目 | 仕様 |
| --- | --- |
| 用途 | 古本フリマの会計。売上管理は補助 |
| 端末 | iPad Safari、横を基本に縦にも対応 |
| 構成 | 軽量な静的HTML/CSS/JavaScript。外部サーバー・登録・ログイン不要 |
| 初期価格 | 100円・200円・400円だけ。300/500円は初期選択肢に出さない |
| 色 | 赤・黄・緑・白・青・白丸の「そ」。色を選ぶと設定された価格を適用 |
| 色の対応 | 赤/黄/緑/白/青/白丸「そ」/白丸「CD」の7マーク。初期はすべて100円。設定から変更可能 |
| 分類 | マークごとに任意の分類名（20文字以内）を設定。初期値は赤文庫・黄新書・緑単行本・白漫画・そその他・CD=CD、青は未分類。マークのボタンと会計明細に分類名を表示（空欄は色名） |
| 会計 | 複数単価・複数色・複数分類を1会計に混在可能 |
| 数量 | 明細ごとに大きな＋/−で増減。「赤 100円 × 2」のように会計欄へ大きく表示。CDを含むため単位は「点」 |
| 支払い | 商品合計、お預かり金額、お釣り。お預かり不足は完了不可 |
| 確定 | 「完了」1回で日時を付けて自動保存。別の売上記録操作は不要 |
| 保存後 | 保存成功を示して次会計へ。保存前に入力を消さない |
| 履歴 | 本日売上・販売冊数、会計履歴、価格/色/分類別集計、CSV出力 |
| 設定 | 価格追加・削除・金額・表示順・生成範囲・刻み幅、色対応変更 |
| 安全 | 価格と色対応を変更しても過去記録に影響しない |

## 最小版の設計判断（実装案。未指定のユーザー事実とは区別）

- 最新の100円設定・全面再構成の承認により、6マークをすべて100円の初期値にする。100/200/400円の候補は保持。旧マーク設定はmarkerVersion:2へ一度再構成し、以後の設定変更は保持する。
- 色を1回タップするごとに、その色の本を1冊追加する。同じ色の再タップでも1冊ずつ加算する。＋/−は数量の訂正にも使える。価格は色から決まり、会計画面で自由上書きしない。
- 分類はマークの設定値から自動で決まる（2026-10-30 ユーザー指定で、会計中の分類選択を廃止）。空欄は「未分類」として保存・集計する。確定時の分類名はsnapshotなので、後で分類名を変えても過去記録は変わらない。
- 初期版は単一レジ・単一の操作タブを基本とする。同一端末の複数タブは書込競合を検知して再読込を案内し、古い状態から確定させない。
- 設定を変更する前に進行中会計を完了するか、確認付きでクリアする。参照中の価格を削除する場合は色の再割当が必要。
- 範囲/刻み幅は設定内の候補一括生成にだけ使用。プレビュー後に適用し、現会計や過去履歴へ反映しない。単純な追加/削除を先に実装する。
- CDも販売点数として内部quantityに含め、画面の単位は「点」とする。
- 一会計の合計、お預かり、数量と積算が安全な整数に収まることを検証。上限値の具体値は実装時に選び、画面に分かるエラーを出す。

## 会計状態と保存

`編集中 → 保存中 → 保存成功 → 次会計`。保存失敗は編集中へ戻し、入力と同一会計IDを維持する。保存中は完了操作を無効化する。

計算は整数円で `total = Σ(unitPriceYen × quantity)`、`change = receivedYen − total`。空会計、数量0のみ、未入力、小数、負数、金額不足、非数、上限超過は完了不可。お預かり欄は数字入力、補助ボタンは「1,000円を入力」のように置換か加算か明記する。

永続化はIndexedDBを第一案とし、取引・明細・採番・取消/差替を同一トランザクションで記録する。アプリからの成功通知はtransaction complete後だけ。request successだけで画面を消去しない。会計IDに一意制約を付け、同一ID再試行は重複登録しない。採番はトランザクション内で行い、取消済み番号も再使用しない。IndexedDB不能時に一時保存へ黙って切り替えない。

## データモデル案（schemaVersion: 1）

| レコード | 主なフィールド |
| --- | --- |
| settings | schemaVersion, revision, prices[{id, amountYen, order}], colors[{id, label, hex, priceId}], genres[{id,label,order}], priceGenerator{min,max,step} |
| receipt | id, receiptNo, committedAt(ISO時刻とoffset), businessDate(端末現地日付), timeZone, items[], quantityTotal, totalYen, receivedYen, changeYen, cumulativeAtCommitYen, correctionOfId? |
| item snapshot | priceId, unitPriceYen, colorId, colorLabel, colorHex, genreId|null, genreLabel, quantity, lineTotalYen |
| void event | id, receiptId, voidedAt, reason, replacementReceiptId? |
| metadata | schemaVersion, nextReceiptNo, revision |

設定は安定したIDで参照するが、履歴表示と再集計にはsnapshotを使用。receiptごとの価格別・色別・分類別購入数はitemsから算出可能とする。累計snapshotは確定当時の値として残し、現在の有効売上累計は取消イベントを除いて再計算する。

本日集計は端末の現地営業日（初期運用は日本）で判定し、端末時刻を利用する。UTC日付の切出しだけで判定しない。取消は元の会計を無効にし元営業日の有効売上から除外。取消操作日時も別に記録する。端末時計をサーバー時刻と称さない。

## 取消と訂正

- 保存後に「直前の会計を取消」を提示。会計番号・金額を示して確認後、取消理由と時刻を追記する。
- 履歴にも取消済み表示を残す。取消を連打しても1回だけ有効。
- 訂正は元会計のコピーを編集してプレビューし、確認後に元会計の取消と差替会計保存を同一トランザクションで行う。途中失敗なら両方変更しない。
- 差替の単価は元snapshotを初期値にし、現在設定へ無断置換しない。旧色・分類が設定から消えていても元の表示を保持する。

## 出力と復元

- CSVはUTF-8 BOM付き・CRLF、引用符/改行/カンマをエスケープ。自由入力ラベルが表計算ソフトの数式と解釈される場合を無害化する。
- 明細1行方式で会計ID/番号/日時/営業日/状態/取消日時/訂正元ID/単価/数量/色/分類/明細金額/会計合計/預り/釣り/確定時累計を出す。会計合計は繰返し列であり、売上集計は有効明細金額を合算する旨を併記。
- CSVは集計用。完全バックアップはsettings・receipts・voids・metadataを含むバージョン付きJSON。復元は検証・件数プレビュー・既存データのバックアップ後、確認付き全体置換のみ。失敗時は既存データを維持する。初期版では複雑なマージを作らない。
- ブラウザを閉じても通常は残る設計だが、消去・容量不足・OS側削除・端末故障に備え、営業終了後は端末外へ保存する。プライベートブラウズは使わない。

## 後続・未確定

分類の運用上の必須性、CDの表示呼称、営業日締め時刻（初期案は現地0時）、金額/数量上限、素材の再配布条件は未確定。初回設定と上記実装案で着手可能。ISBN、在庫、決済連携、クラウド同期、利用者管理、テーマ追加は初期対象外。

## 2026-10-30 追加指定

- マーク欄の見出しは「購入数ぶんタップしてください」。ボタンは色名ではなく分類名を表示する（以前の「レジ画面に出さない」指定を置き換え）。
- 設定に「設定をすべて初期状態に戻す」を置く。確認後、価格候補100/200/400円・全マーク100円・分類名初期値で保存する。確定履歴は物理削除しない規則に従い、売上・取消・訂正の記録は消さない。
- 100円単位の運用を前提に、お預かり候補を「ちょうど」の次に表示する。合計を500円・1,000円・5,000円・10,000円単位で切り上げ、合計より大きいものを重複なく昇順に全部出す（例: 1,300円 → 1,500/2,000/5,000/10,000円）。
